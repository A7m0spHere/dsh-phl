# PHL 0.1.0-rc.2

这一版第一次同时提供 Windows 与 macOS 安装包。macOS 侧补齐了原生窗口控制、钥匙串凭据与「能真正找到 Node」的启动链路；Windows 侧继续收窄启动、插件与试用升级的边角问题，并统一了圆角视觉与实例页的空状态引导。

## macOS（本版首次提供）

- **原生窗口控制。** 使用系统红绿灯，标题栏支持原生拖拽与双击缩放，Web 内容延伸到标题栏之下；全屏时红绿灯收起，标题栏出现「退出全屏」按钮（⌃⌘F 同效）。关闭确认与运行中实例保护与 Windows 一致。
- **API 密钥进钥匙串。** 供应商 API Key 存入系统 Keychain，与 Windows 凭据管理器共用同一套 `PHL:provider:<id>` 命名；新构建首次访问条目可能弹一次钥匙串授权框。
- **能找到 Node 的启动链路。** 从 Finder 启动的应用看不到 shell 里的 PATH——PHL 现在按 PATH、fnm、nvm、Homebrew 等常见安装位置逐个探测并实际运行验证，取第一个可用的**绝对路径**；运行时页显示的版本就是启动真正执行的那个。该目录会注入 DSH 子进程的 PATH，实例自定义 PATH 仍然优先，原有条目去重保留。
- **停止即停整棵树。** 停止实例先对整个进程组发 SIGTERM，给 DSH 收尾会话文件的时间，宽限后对拒绝退出的部分发 SIGKILL；只有实例自己领导的进程组会被组播，绝不波及 PHL 自身。此前 Unix 停止只对直接子进程发一次硬杀，DSH 拉起的插件进程会残留。
- 安装包未签名未公证，首次打开需右键 →「打开」（详见安装说明）；当前仅提供 Apple Silicon（arm64）版本，Intel Mac 未做真机验收。

## 可靠性与正确性

- **启动失败看得见、可行动。** WebUI 页面级启动失败不再默默白屏：页面给出探测到的失败原因与可执行的修复入口。
- **依赖安装器跟着实例的运行时走。** 版本依赖安装不再假设系统 `node`，改为通过实例绑定的运行时解析 npm；Finder/窄 PATH 环境下同样可安装。
- **试用升级如实处理实体插件包。** 副本检测目标版本不再携带或已改名的实体包，能自动替换失配包并在预览中如实报告；版本链接在 `/var` 与 `/private/var` 互指、Windows 8.3 短名与大小写差异下都能正确重定向。
- **DSH 内置插件只读盘点。** 插件页区分 DSH 捆绑的内置插件与用户安装的插件，内置项只读展示，不再混入可卸载列表。
- **「最新」徽章跟着最新发布走。** GitHub 已发而 npm 未上架的版本占据「最新」位且保持不可安装的诚实标注；npm 滞后不再把可安装版本误标为 Legacy。「npm 未收录」徽章补了悬停说明。
- **凭据保存失败的错误更诚实。** 凭据管理器不可用或读不出旧值时，错误点名受影响的供应商并说明「旧密钥未能读出」，而不是暗示已被覆盖。
- **tar 包保留执行权限。** Unix 上解压 Node 版本包保留可执行位，并只在暂存目录的 Node 通过版本探测后才提交安装，失败的安装不再污染运行时目录。

## 使用体验

- 圆角体系整体收敛（卡片 10px、按钮 8px、标签 4px），实例卡片操作按钮常显、网格卡片操作独立成行，首次进入实例页出现引导卡片。
- 页头操作区可换行，窄窗口不再把副标题挤成碎片；macOS 上快捷键提示显示 ⌘K。

## 说明

- **Windows**：rc.1 及更早的可自动更新版本可在「设置 → 关于」直接检查并安装本版本；安装包未做 Authenticode 签名，SmartScreen 提示见安装说明。
- **macOS**：仅 Apple Silicon；未签名未公证，首次打开需右键 →「打开」；本版不含应用内自动更新，升级需手动下载新 DMG。
- **Linux**：暂无安装包，凭据管理器在 Linux 上仍不可用（保存含密钥的 API 配置会明确报错）。
- rc 阶段数据格式与界面仍可能调整；同一数据目录不支持多个 PHL 窗口同时管理同一个实例。
