# PHL 0.1.0-alpha.4

这一版集中修正实例、Runtime、整合包与任务状态的可靠性问题，并让安装、启动和失败状态更容易看懂。

## 可靠性与安全

- 收紧 Windows 路径与实例清单校验，避免特殊目录名、未知清单格式或不可读清单进入破坏性操作。
- 删除 Runtime 前会检查实例引用，并先把目录移出可见安装区；失败时不会把半删除目录继续显示为可用。
- 数据目录迁移只接受 PHL 当前管理的源目录；迁移、克隆和快照中的 junction 路径不再受命令行元字符影响。
- `.phlpack` 拒绝 NTFS 备用数据流、大小写碰撞以及“声明不含会话但实际携带会话”的包；CLI 解包不再覆盖已有目录，失败构建也不会留下假产物。
- 已保存的供应商密钥只会发往该供应商配置中登记的同一网络源（协议、主机和端口均一致）。
- 多个 PHL 进程写入运行实例登记时会合并记录，长任务的临时句柄释放也不会再把成功任务短暂标成“被中断”。

## 使用体验

- 接入本机 DSH 后会保存规范的版本绑定；版本正在安装时，启动提示会明确显示“安装中”，不会再误报“未安装”。
- 版本、Runtime、插件、快照和删除任务统一显示真实阶段与失败结果；任务中心会保留最近失败提示。
- 会话迁移支持全选，复制进度按实际完成量显示。
- 设置新增“启动实例后自动打开 WebUI”；关闭后仍可从就绪提示手动打开。
- 运行中的实例会提前禁用创建/回滚快照，并说明需要先停止；“关闭动画”现在也会停用 CSS 动画与过渡。
- 插件兼容性标签补充解释，实例菜单增加“查看详情”，GitHub-only DSH 版本直接打开对应 Release。
- 模型元数据缓存更快跟进新模型，并避免把旧回退信息误当成上游事实。

## 说明

- alpha.3 用户可以在“设置 → 关于”中直接更新；alpha.2 及更早版本仍需先手动安装 alpha.3 或更高版本。
- 安装包仍未做 Authenticode 代码签名，首次下载与运行可能出现 SmartScreen 提示。
- alpha 阶段的数据格式与界面仍可能调整；同一数据目录不支持用多个 PHL 窗口同时管理同一个实例。
